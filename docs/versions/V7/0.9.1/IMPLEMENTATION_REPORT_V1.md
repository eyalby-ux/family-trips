## Section 2 choice: a sibling function, and why
`netlify/functions/game-content.mjs` (path `/api/familytrips-game-content`), **not** another entry in `smart-import.mjs`'s `OPERATIONS`. That map is built around reading a document (`prepareSource`, place validation, classification); none of it applies to writing questions, and a sibling keeps the PDF/TIFF/undici dependencies out of the game function. It reuses the same `_shared/` modules — `authorize`, `registerOrVerifyTrip`, `consumeDailyQuota` (the **same** 10/day pool; exactly one consume per build, the bounded top-up inside a build is not a second tap), `writeAudit` — and the same structured-output call shape. `smart-import.mjs` is untouched.

## Reuse by `0.9.3` (Pantomime)
`netlify/functions/_shared/game-content.mjs` holds the whole mechanism, generic over a list of `fields`: `normalizeForMatch`, `dropRepeats(list,history,fields)`, `generateWithRepeatGuard({callModel,history,count,fields})` (build → drop repeats → **one** top-up for the missing count → ship short), `buildTripContext`, `cleanHistory`, `HISTORY_CAP=60`; plus the Trivia schema / prompt / instruction. Client side `capHistory` (in `src/games.js`) is generic too. Pantomime adds: a `generate_pantomime` entry in `KINDS` of `game-content.mjs` (`fields:['text']`, `listKey:'phrases'`, its own schema/prompt), `askedPhrases` on its record, and the client call. Nothing in the mechanism is Trivia-specific.

## Repeat prevention (as built)
History = `askedQuestions` on the game record (`{question,answer}`, 60 most recent, oldest dropped first, survives a rebuild); sent on **every** generation call as an explicit exclusion list in the instruction text; after generation a normalized match (trim / lowercase / strip punctuation, Unicode-aware) on question **or** answer against the history **and** the kept items drops repeats; then one top-up call (its payload carries the history plus what was kept); still short → ships short (the client says so in a toast instead of staying silent). Tests assert the exclusion list is in the **second** call's payload (AI mocked), the top-up count, that it never loops, never exceeds the target, and the 60-cap.

## What didn't check out against source / scope notes
1. **No static bank or `deck` pointer ever existed.** The scope speaks of replacing "the record's current static-bank pointer"; the built-in record only had instructions text. `deck` is simply new.
2. **Answer-match is aggressive by design** (scope: compare question *and* answer): two different questions with the same short answer count as a repeat. Fine for kid trivia; a deck can end up slightly short on a small destination.
3. **Added (not in the scope):** a `confirm()` before a rebuild only when a game is in progress (a stray tap would wipe the tally); the "ship short" toast; Trivia's header reuses `backRow` (given an optional `action` param) so the one-back-button pin still holds.
4. **Mockup deviations:** no ✨ emoji on the button (the app uses icons, not emoji, since Phase 3); chips are 44px (the mockup's 40px fails the §9 tap-target audit); progress shown as `שאלה N/M` in the card (the mockup put it in the top bar, which this app doesn't have per game).

Step 0 (replace the repo's `V165` copy) was blocked by the environment's permission guard on the first attempt and is **pending the Product Owner's instruction** — not done.
