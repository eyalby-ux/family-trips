**`V6-F65`** (fabricated venue/provider name) — still open, and this is important: on a fresh `AE-007` reimport, `location` now correctly shows the generic "גן החיות" (good — that part of the fix worked), but `provider` now shows "החברה להגנת הטבע" (Society for the Protection of Nature), attributed by the app's own warning text to "identified from the logo/text on the ticket." **Eyal has directly confirmed against the actual source: this text does not appear anywhere on the ticket.** So the negative-example prompt guidance reduced the surface symptom (no more substituting a well-known zoo brand for the whole venue) without fixing the underlying behavior: when the model can't actually read something (this ticket's small stylized logo, which Claude Code and Eyal both independently found too unclear to confirm), it's still reaching for a plausible real-world organization name and presenting it as if it were read from the source, rather than saying it can't be determined. This is a more subtle and arguably more dangerous version of the same defect, since claiming a specific textual source ("identified from the logo") makes the fabrication read as more credible, not less. Please investigate the extraction prompt's actual behavior when a source element is visually present but not confidently legible — the correct behavior is to say so (flag as illegible/unconfirmed) rather than output any specific name, however the prompt currently arrives at "well, it's probably this."
